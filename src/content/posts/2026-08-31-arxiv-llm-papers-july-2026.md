  ## 1. CrossBERT: 把"表示学习"和"重建"解耦的可扩展文本编码器

  **论文**: Separating Representation from Reconstruction Enables Scalable Text Encoders
  **作者**: Megi Dervishi, Mathurin Videau, **Yann LeCun**（NYU / Meta FAIR）
  **链接**: https://arxiv.org/abs/2607.04011

  ### 1.1 问题背景

  解码器（GPT 系）这些年疯狂扩参，但编码器（BERT 系）自 2018 年以来架构几乎没变，而且缩放表现很差。作者用"冻结评估"（frozen probing）这一新视角发现：**BERT 的表示随模型变大反而越来越"不可用"**——perplexity 一直在降（重建能力在涨），但冻结特征在下游任务上的表现随规模增大而急剧退化，超过 500M 参数后甚至不如自己 10 倍小的模型。根因在于 BERT 的"扁平设计"：表示学习与 token 重建（MLM）目标强耦合，模型越大会越"过度专业化"于逐词重建，牺牲高层语义抽象。

  ### 1.2 别人怎么解决的

  主流补救是"事后弥补"：训练后用对比学习做后训练（SimCSE、E5、GTE 等）或加 token 级目标（MEXMA）。ELECTRA 用 RTD（判别式重建）替代 MLM，但实验显示 RTD 会进一步扭曲句向量几何。这些方法都在"治标"——重建目标仍然与表示耦合，只是换个方式掩盖。

  ### 1.3 他们怎么解决的

  提出 **CrossBERT**，借鉴视觉 MAE 的双部分设计：
  - **输入切分**：可见 token 进编码器，掩码 token 进 predictor；
  - **预测器是浅层模块**（约编码器 1/4 深度），只与编码器表示做 cross-attention，掩码 token 之间**禁止 self-attention**，迫使预测器只能"读"编码器学到的表示来满足重建目标——表示学习和重建被物理隔离；
  - 配 RoPE、RMSNorm 等现代优化；支持 ≥50% 的高掩码率，并提出 **Complementary Masking Strategy** 让所有 token 都有梯度，吞吐量提升 1.5–2×、样本效率提升 2×。

  ### 1.4 实验与效果
  设计了"冻结评估"协议（GLUE 线性探针 + kNN + MTEB frozen）：
  - **鲁棒性**：从全量微调切到冻结评估，BERT 在 MTEB(eng,v1) 掉 10+ 分（53.9→42.1），CrossBERT 几乎不掉（冻结 53.6，保留 99%）；
  - **检索能力**：Retrieval 任务 40.7 vs 19.2，翻倍以上（BERT/MLM 在任何规模下检索都趋近 0，结构性地学不会稠密检索）；
  - **规模扫描**：CrossBERT 在所有规模单调提升，且大模型下"冻结的 CrossBERT 甚至超过全量微调的 BERT"；GLUE 线性探针比 BERT 高 6.4 分。

  ### 1.5 优缺点与改进
  - **优点**：直击 BERT 缩放失效的根因（架构级修复而非后训练打补丁）；设计优雅、与具体重建目标无关；冻结特征即可用，省掉昂贵的对比微调。
  - **缺点**：线性探针与全量微调仍有约 13 分差距（部分归因于简单的 mean-pooling）；实验以英文基准为主；预测器形状还需消融调参。
  - **改进方向**：作者自己提出换掉 MLM 用其他前置任务、与 T5 式自回归解码器对比；也可考虑注意力式池化缩小探针差距。

  ## 2. C-MTP: 连续思维链训练的"两个世界"

  **论文**: Training Continuous Chain of Thought Models: A Tale of Two Regimes
  **作者**: Varun Yerram, **He He**（NYU）, **Eunsol Choi**（UT Austin）
  **链接**: https://arxiv.org/abs/2607.16972

  ### 2.1 问题背景
  连续思维链（Continuous CoT，如 Coconut、CODI）用一串密集潜向量替代冗长的文字推理链，号称能大幅加速推理（解码 N 个 token 变 N 个向量）。但此前方法训练时需**自回归地逐个生成潜向量**（间接监督），速度慢；且所有评估都只用简化、短（<100 token）的推理痕迹，真实场景中的长痕迹（几百 token）表现未知。

  ### 2.2 别人怎么解决的

  - **间接监督派**（Coconut、CODI、SIM-cot）：训练时让模型自回归生成潜向量序列，再约束其与教师模型的最终隐藏状态对齐。效果好但训练慢、潜步骤数需预先固定，且 SIM-cot 发现 K 增大时潜变量退化，需逐步骤监督补救；
  - **直接监督派**（CoLaR）：把推理痕迹每 s 个 token 压缩成一个潜向量，训练时采样子轨迹并预测整个 token 组，用参数化高斯近似多峰分布。

  ### 2.3 他们怎么解决的
  提出 **C-MTP**（Continuous Multi-Token Prediction）：更简单的直接监督——**每个潜向量 = 待压缩 CoT 片段所有 token 嵌入的平均**，再用多 token 预测目标训练。无需训练时自回归生成潜向量，实现简单、训练快。

  ### 2.4 实验与效果（关键发现）
  在 LLaMA-3.2-1B-Instruct 等 1–1.5B 模型、数学任务、三档推理痕迹上实验：
  - 简化痕迹（GSM8k-Aug）：C-MTP 优于 CoLaR，与较慢的间接监督方法持平，且更省样本、OOD 泛化更好；
  - 半自然长痕迹：间接监督反超（其循环训练能更好压缩长链，直接监督受限于原始痕迹长度、推理时 teacher-forcing 误差累积）；
  - **真实复杂痕迹（≥几百 token）：两类方法全部崩溃，准确率掉约 65%**（只有 CoT 的 30–35%）——这是本文最重要的负面结论：现有基准高估了连续思维链的实际可用性。

  ### 2.5 优缺点与改进
  - **优点**：C-MTP 简单、快、省样本；论文提供了迄今最诚实的连续 CoT 评测，暴露了领域瓶颈。
  - **缺点**：结论局限于 1–1.5B 模型和数学任务；直接监督本身天花板受限。
  - **改进方向**：作者建议混合方案——token 推理与潜空间推理自适应切换（SwiReasoning、ThinkRouter、LightThinker++ 等），并扩展到代码、多跳问答和更大模型。

  ## 3. 可提取记忆的"第一性原理"：给记忆提取建立校准标准

  **论文**: Extractable Memorization From First Principles
  **作者**: A. Feder Cooper（Yale/Stanford）, Marika Swanberg（Google Research）, Jamie Hayes（Google DeepMind）, **Percy Liang**（Stanford）等
  **链接**: https://arxiv.org/abs/2607.12649

  ### 3.1 问题背景
  "从 LLM 里提取训练数据"（extractable memorization）是隐私研究核心问题，但现有文献有**两个相反的效度缺陷**：一类高估——用太短的序列（分不清是记忆还是可预测性）或提示词里直接泄露目标；另一类低估——模型本来就能复述没训练过的网络文本，所以提取不足为凭。两边都缺一个关键校准：**提取出的序列生成概率要高到"只能用记忆解释"的程度**。

  ### 3.2 别人怎么解决的
  此前的提取攻击（提示式提取、对抗搜索、divergence attack）和记忆定义（verbatim、near-verbatim、k-extractability）都停留在"跑通流程 + 人工 sanity check"层面，验证环节（verify）要么缺失要么不规范，没有把对照变成校准过的决策。

  ### 3.3 他们怎么解决的
  提出**匹配对照（matched comparison）+ 保形检验（conformal test）**框架：
  1. 对每个候选序列，测其在提示下的生成概率；
  2. 构造"可比的非训练序列"（如训练截止日后发布的维基条目）作为对照基线；
  3. 用保形检验把记忆判定校准到指定的假阳性率（FPR），得到个体级和总体级的记忆率估计；
  4. 重新定义"可提取记忆"：**既通过校准阈值（memorized），又要在现实查询预算内能以高概率被采样出来（realistically extractable）**——二者缺一不可。

  ### 3.4 实验与效果
  - OLMo 2 32B + 维基百科：现在流行的 10-token 短后缀提取，**表观提取率中约 24% 是假阳性**（纯可预测性）；
  - 图书普查（固定文档 vs 匹配的非训练图书）：50-token 后缀的校准阈值低到 10⁻²⁷～10⁻²¹，意味着许多被"验证为记忆"的序列实际采样概率极低——用"可提取记忆"来称呼它们是名不副实；
  - 结论：文献中大量"提取概率"数字既不能证明记忆（未校准），也不能证明可提取（概率太低）。

  ### 3.5 优缺点与改进
  - **优点**：首次给记忆提取建立严格的统计校准框架，让"记忆率"可复现、可比对；对隐私诉讼等现实场景（如何证明某本书被记住了）有直接意义（作者包含 Stanford 法律学者 Lemley/Ho）。
  - **缺点**：匹配对照的构造是 best-effort（序列分布完全对齐很难）；校准阈值低到现实不可提取时，框架给出的是"记忆存在但不可提取"这种微妙结论。
  - **改进方向**：设计更好的匹配对照采样；把查询预算与提取流程的交互建模进来。

  ## 4. Right in the Right Way: 用对抗判别器补全 RLVR 的"不可验证之美"

  **论文**: Right in the Right Way: LM Training with Verifiable Rewards and Human Demonstrations
  **作者**: Mehul Damani, Isha Puri, Idan Shenfeld, **Jacob Andreas**（MIT）
  **链接**: https://arxiv.org/abs/2607.01181

  ### 4.1 问题背景
  可验证奖励强化学习（RLVR，如代码/数学上跑测试）已成为主流后训练范式，但它**只优化"能客观打分"的部分**，忽视风格、结构等主观不可验证属性，导致业界熟知的失败模式：多样性坍缩、回答腔调不自然、奖励黑客（reward hacking）。

  ### 4.2 别人怎么解决的
  传统两派各管一头：RLVR 管"对不对"，SFT/RLHF 管"像不像人"（靠人类偏好标注或演示）。但 RLHF 奖励模型代价高、易被劫持；纯 SFT 又达不到 RLVR 的任务上限。GAN 式文本生成（SeqGAN 等）在旧模型上有过探索，但没与可验证奖励结合。

  ### 4.3 他们怎么解决的
  提出 **VARL（对抗生成器-判别器框架）**：
  - **生成器**：用 RL 最大化"可验证任务奖励 + 对抗奖励"的加权（gated）组合；
  - **判别器**：与策略同步训练，学会区分"人类写的输出"与"模型输出"，作为人类输出分布的学得代理，给风格、结构这些难以写成标量奖励的属性提供反馈；
  - 关键工程点：判别器作用的**特征空间**很重要——对故事生成用"摘要后的故事"而非原始故事喂判别器，避免判别器依赖长度等表层特征。

  ### 4.4 实验与效果
  三个领域（都保留 RLVR 的精度收益）：
  - **Bug 修复**：与 RLVR 基线精度持平，但编辑距离显著更低（更像人改的代码）；
  - **故事生成**：胜率显著提升，且输出更多样、更像人类；
  - **奖励黑客基准**：几乎完全消除模型"钻空子"行为，同时保持高分；
  - 消融：原始故事做特征空间会降低 verifier reward 且训练震荡。

  ### 4.5 优缺点与改进
  - **优点**：用最少的机制（一个判别器）把 RLVR 和 SFT 的长处接起来，是"可验证目标 + 人类演示"的简洁通用配方；可扩展性强于手工设计风格奖励。
  - **缺点**：对抗训练固有的非平稳性/训练不稳定（靠工程手段压制但未根除）；特征空间选择高度影响学到的属性；需要可验证奖励 + 中等数量演示同时可用。
  - **改进方向**：更好的奖励融合目标；特征空间自动化设计；演示稀少或 verifier 有噪的场景。

  ## 5. LLM 检测是一场"干预"：战略用户行为下的下游影响

  **论文**: LLM Detection as an Intervention: Downstream Impact under Strategic User Behavior
  **作者**: **Meena Jagadeesan, Tatsunori Hashimoto**（Stanford）, **Jon Kleinberg**（Cornell）
  **链接**: https://arxiv.org/abs/2607.19300

  ### 5.1 问题背景
  检测 AI 生成内容（水印、分类器、语言风格启发式）被越来越多的机构当作"干预手段"来治理 AI 滥用。但**检测器不只影响被检测属性本身，还会改变用户如何激励性地使用 LLM**——用户会策略性地决定"用多少 LLM、怎么后处理规避检测"。不完美的检测器在这种博弈下可能产生反直觉的负面效果。

  ### 5.2 别人怎么解决的
  已有工作（Liang et al. 量化论文中 LLM 使用率、Geng & Trotta 的人机共进化）大多只做**描述性测量**（检测率、词频变化），缺少对用户激励反应的建模；检测文献（水印、分类器）则聚焦检测精度本身，几乎不分析检测作为干预对下游指标的影响。

  ### 5.3 他们怎么解决的
  构建一个**精简的博弈论模型**：用户按效用最大化选择 LLM 使用比例 α 和后处理强度（降低被检测属性），检测器按被检测属性施加惩罚。从均衡中推导出可证的反直觉结论：
  - **检测可能反而让人类更多使用 LLM**（当检测属性与质量提升相关时，用户通过"更多使用+更少后处理"对冲惩罚）；
  - 即使被检测属性本身是降质量的，引入检测器仍可能让输出质量**更差**；
  - 检测器对"被检测属性"本身总是产生干净的"先升后降"（rise-then-fall）模式。

  ### 5.4 实验与效果
  - 理论：均衡分析 + 定理刻画上述效应；并证明即使惩罚任意大，劣化效应依然存在；检测"质量提升型特征"能保证弱化 LLM 使用，但消除不了质量扭曲；
  - 实证：2013–2025 年 arXiv 摘要词频分析（GPT-5.4-mini 作为风格词裁判），**LLM 时代风格词呈现显著更多的"先升后降"模式**，与模型预测一致。

  ### 5.5 优缺点与改进
  - **优点**：把检测从"度量问题"重构为"博弈干预问题"，理论干净、有实证呼应，对政策制定（该检测什么特征）有直接启示。
  - **缺点**：模型是 stylized 的（线性质量函数、同质用户、理想化后处理）；实证仅覆盖词频一种属性。
  - **改进方向**：异质用户与多检测器博弈、动态检测策略、把水印等具体机制纳入模型。

  ## 6. SAO: 单次 rollout 的异步强化学习，驯服 Agent 训练

  **论文**: Single-Rollout Asynchronous Optimization for Agentic Reinforcement Learning
  **作者**: Zhenyu Hou, Yujiang Li, **Jie Tang, Yuxiao Dong**（清华大学；实习于 Z.AI）
  **链接**: https://arxiv.org/abs/2607.07508

  ### 6.1 问题背景
  RL 已成为 LLM 后训练的核心，但传统 RL 流水线是**同步、批量交替**的：等一批 rollout 全部完成才更新一次模型，对长时程 Agent 任务（一次轨迹可能几万 token）效率极低。异步 RL（边出 rollout 边更新）是出路，但现有异步系统只强调吞吐量，**训练稳定性与 off-policy 问题几乎没人系统解决**——尤其 GRPO 依赖组内相对奖励的 group-wise 采样，天然不适配"每个提示只有一条轨迹"的异步 Agent 训练。

  ### 6.2 别人怎么解决的
  GRPO 系（含 VAPO 等带 clip-higher、重要性采样的改进）是当前主流，但同步+组采样；异步 RL 系统（如各种 async RLHF/RLVR 框架）把 GRPO 硬搬到异步场景，导致训练坍塌、策略漂移。

  ### 6.3 他们怎么解决的
  提出 **SAO（Single-rollout Asynchronous Optimization）**，三件套：
  - **单 rollout 采样**：每个 prompt 只采一条轨迹，替代组采样，从根上消除组内相对基线带来的 off-policy 偏差，并天然适配异步与在线学习；
  - **值模型（critic）优势估计**：用训练的值模型替代组内均值做 baseline（配合精心设计的价值模型训练方案），单条轨迹也能算 advantage；
  - **严格的双侧 token 级裁剪**：稳定策略更新，防止异步陈旧数据导致的策略跳变。

  ### 6.4 实验与效果
  基于 Qwen3-30B-A3B，覆盖 Agent 推理、代码与在线写作模拟：
  - 标准 GRPO 在约 **160 步即性能坍塌**；GRPO+DIS（其提出的去偏采样）可稳定但效果不如 SAO；
  - **SAO 稳定训练 1000 步**，在 Agent 推理和代码基准上一致超过 GRPO 及其变体；
  - 在线学习模拟（奖励偏好随时间切换的写作风格任务）：SAO 能随环境反馈快速对齐新偏好，优于 Running-Mean 基线。

  ### 6.5 优缺点与改进
  - **优点**：解决了异步 Agent RL 的稳定性/off-policy 真问题，工程与算法结合紧密；在线学习能力是未来 Agent 持续自我进化的关键。
  - **缺点**：依赖值模型与 rollout log-prob 基础设施（异步生成时保存 token 级概率）；结论基于 30B MoE 的 Agent/代码任务，未必迁移到小模型、稠密奖励或传统 RLHF。
  - **改进方向**：扩展到小模型与非 Agent 场景、真实在线环境的安全护栏。
